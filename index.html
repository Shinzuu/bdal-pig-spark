BDAL Pig — join two datasets, then Spark setup

Part 1: process two CSVs with Apache Pig (filter · project · sort · group · join → DUMP). Part 2: download & set up Apache Spark. Pig steps verified end-to-end on a real Hadoop 3.4.1 cluster.

The two datasets (join key = student_id)

students.csv id,name,age,grade scores.csv id,subject,score
1,John,18,A · 2,Alice,19,B
3,Bob,17,A · 4,David,20,B		 1,Math,85 · 2,Math,78
3,Science,90 · 4,Math,88

What is DUMP? Pig is lazy — LOAD/FILTER/JOIN build a plan but run nothing. DUMP x is the trigger: it launches the MapReduce job(s) and prints the result. "Showing the output" and "showing the DUMP" are the same thing. (STORE x INTO 'path' = same, but writes to a file instead of the screen.)

🐷 Part 1 · Apache Pig — join two datasets

1 · Start the cluster

start-dfs.sh && start-yarn.sh
jps
start-dfs.sh && start-yarn.sh
jps

macOS Hadoop (Temurin JDK 11) uses the same start scripts as Linux.

Recommended: WSL2 Ubuntu — then every command on this page is identical to Linux. Open Ubuntu and run:

start-dfs.sh && start-yarn.sh
jps

Native Windows instead? Use start-all.cmd and expect 4 daemons (no SecondaryNameNode split).

jps → NameNode, DataNode, SecondaryNameNode, ResourceManager, NodeManager (5 daemons on Linux/mac/WSL). Pig in mapreduce mode needs these running.

2 · Create an HDFS folder + verify

hdfs dfs -mkdir -p /piglab
hdfs dfs -ls /

-ls / now lists /piglab. This is where the two input files live in HDFS.

3 · Move the 2 files local → HDFS + verify

Run from the folder holding the two CSVs (create them first if needed — contents are in the box above).

hdfs dfs -put -f students.csv scores.csv /piglab/
hdfs dfs -ls /piglab
Found 2 items -rw-r--r-- 1 ... 43 ... /piglab/scores.csv -rw-r--r-- 1 ... 49 ... /piglab/students.csv
⚠ No such file on the put → you're not in the folder with the CSVs. The -f lets you re-put safely.

4 · Save the Pig script as script.pig

One line per transformation. Covers all five verbs the objective asks for.

-- load both datasets from HDFS, with a schema
students = LOAD '/piglab/students.csv' USING PigStorage(',')
    AS (student_id:int, name:chararray, age:int, grade:chararray);
scores   = LOAD '/piglab/scores.csv'   USING PigStorage(',')
    AS (student_id:int, subject:chararray, score:int);

filtered_students  = FILTER students BY age > 18;              -- FILTER
projected_students = FOREACH filtered_students GENERATE name, grade;  -- PROJECT
sorted_students    = ORDER projected_students BY name ASC;     -- SORT
grouped_scores     = GROUP scores BY subject;                 -- GROUP
joined_data        = JOIN students BY student_id, scores BY student_id;  -- JOIN

DUMP sorted_students;
DUMP grouped_scores;
DUMP joined_data;

5 · Go to the folder + run the script

cd ~/piglab
pig -x mapreduce -f script.pig

Runs on the cluster (real YARN jobs — slow, ~1–2 min per DUMP). For a fast dry-run off-cluster use pig -x local -f script.pig (seconds). Progress: localhost:8088. Both modes gave identical output — verified on this PC.

⚠ Input path does not exist → files aren't in /piglab (redo step 3). ⚠ file script.pig does not exist → wrong folder.

6 · The output — 3 DUMPs

sorted_students (age>18 → Alice, David; projected to name,grade; sorted):

(Alice,B) (David,B)

grouped_scores — each subject → a bag of its rows, shape (key,{tuples}):

(Math,{(4,Math,88),(2,Math,78),(1,Math,85)}) (Science,{(3,Science,90)})

joined_data — all 4 match 1:1 on student_id, fields concatenated:

(1,John,18,A,1,Math,85) (2,Alice,19,B,2,Math,78) (3,Bob,17,A,3,Science,90) (4,David,20,B,4,Math,88)

Bag order isn't guaranteed — a differently-ordered Math bag is still correct.

7 · Run it a few times for different DUMPs

Same script, one DUMP at a time — that's the "he edited and re-ran it" bit:

DUMP filtered_students;
(2,Alice,19,B) (4,David,20,B)
DESCRIBE grouped_scores;

DESCRIBE prints the schema, not data: grouped_scores: {group: chararray, scores: {(student_id,subject,score)}}.

⚡ Part 2 · Apache Spark — download & setup

Every command below was run and captured on a real Hadoop 3.4.1 / Java 11 box — same standard as Part 1. Spark 3.5.9 is pinned on purpose: Spark 4.x needs Java 17, but 3.5.9 runs on the same Java 11 as your Hadoop/Pig, so nothing else changes.

8 · Download Spark 3.5.9 (bundled for Hadoop 3)

Grab it next to your Hadoop/Pig install so all the big-data tools live together.

cd ~/bigdata
wget https://archive.apache.org/dist/spark/spark-3.5.9/spark-3.5.9-bin-hadoop3.tgz
cd ~/bigdata
curl -LO https://archive.apache.org/dist/spark/spark-3.5.9/spark-3.5.9-bin-hadoop3.tgz

Recommended: WSL2 Ubuntu — same commands as Linux. Native Windows Spark needs winutils.exe + HADOOP_HOME and is fragile; WSL2 avoids all of it.

cd ~/bigdata
wget https://archive.apache.org/dist/spark/spark-3.5.9/spark-3.5.9-bin-hadoop3.tgz
⚠ The full tarball is ~383 MB. If yours is tens of MB, the download was cut short — delete and re-fetch, or extraction later will be missing bin/ and jars/.

9 · Extract + make a stable spark symlink

tar xzf spark-3.5.9-bin-hadoop3.tgz
ln -sfn spark-3.5.9-bin-hadoop3 spark
ls spark/bin/ | grep spark-submit
spark-submit spark-submit2.cmd spark-submit.cmd

The symlink means SPARK_HOME never changes when you upgrade later — just re-point spark.

10 · Set SPARK_HOME + PATH

Add these to ~/.bashrc (Linux/WSL) or ~/.zshrc (macOS), then re-source. JAVA_HOME must point at the same Java 11 Hadoop uses.

export SPARK_HOME=~/bigdata/spark
export PATH=$SPARK_HOME/bin:$PATH
source ~/.bashrc

spark-submit is now on your PATH. Confirm with the next step.

11 · Verify the install — version banner

spark-submit --version

12 · First job — SparkPi (local mode)

The bundled example estimates π by Monte-Carlo. local[2] = run on 2 cores, no cluster needed.

spark-submit --class org.apache.spark.examples.SparkPi --master local[2] $SPARK_HOME/examples/jars/spark-examples_2.12-3.5.9.jar 100
Pi is roughly 3.1412755141275515

Any value near 3.14 means Spark ran an end-to-end job. More samples (the 100) → closer to π.

13 · The Spark echo of the Pig lab — read a CSV

Same students.csv, same filter/project/sort — but as a Spark DataFrame. Start the shell from the folder holding the file:

cd ~/sparklab && spark-shell --master local[2]

Then paste these three lines. Note file:/// — see the gotcha below.

val df = spark.read.option("inferSchema","true")
  .csv("file:///home/USER/sparklab/students.csv")
  .toDF("student_id","name","age","grade")
df.printSchema()
df.filter($"age" > 18).select("name","grade").orderBy("name").show()

printSchema — types inferred, no manual AS like Pig needed:

root |-- student_id: integer (nullable = true) |-- name: string (nullable = true) |-- age: integer (nullable = true) |-- grade: string (nullable = true)

show() — age>18, projected to name+grade, sorted — identical result to the Pig DUMP:

+-----+-----+ | name|grade| +-----+-----+ |Alice| B| |David| B| +-----+-----+
⚠ Connection refused … localhost:9000 on .csv("students.csv")? Your core-site.xml sets fs.defaultFS=hdfs://localhost:9000, so Spark looks in HDFS. Either start HDFS and -put the file, or force local disk with the file:///absolute/path scheme shown above (swap USER for your username).
